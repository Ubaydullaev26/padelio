# Sprint 0 · Полевая валидация — план и материалы

**Цель:** до написания кода подтвердить (или опровергнуть) две гипотезы:
1. **Предложение:** клубы готовы вести всё расписание в нашей системе и подпишут LOI (нужно ≥3 клуба-якоря).
2. **Спрос:** игроки готовы бронировать онлайн с предоплатой (или хотя бы 50/50 с оплатой на месте).

**Длительность:** 2–3 недели. **Исполнитель:** фаундер лично (делегировать нельзя — это ещё и построение отношений с владельцами).

## Чек-лист Sprint 0

- [ ] Перепись всех падел-клубов Ташкента → [шаблон переписи](club-census-template.md)
- [ ] 10+ интервью с владельцами/админами клубов → [скрипт](club-interview-script.md)
- [ ] 3–5 подписанных LOI → [шаблон LOI](loi-template.md)
- [ ] 20+ интервью с игроками → [скрипт](player-interview-script.md)
- [ ] Юридическая проверка → [чек-лист юристу](legal-checklist.md)
- [ ] Сводный отчёт с решением go / pivot / no-go

## Где искать респондентов

**Клубы:** 2GIS/Google Maps по запросам «падел», «padel»; Instagram-геотеги; Telegram-каналы клубов; вопрос в каждом клубе «а какие ещё знаете?» (снежный ком — на малом рынке все друг друга знают).

**Игроки:** прямо в клубах между матчами (лучшее место — люди расслаблены и говорят охотно); Telegram-чаты падел-комьюнити Ташкента; тренеры (попросить познакомить с учениками); свои знакомые — только для прогона скрипта, их ответы не считаем (biased).

## Правила интервью (The Mom Test)

1. Спрашиваем о **прошлом поведении**, не о будущих намерениях. Не «пользовались бы вы ботом?» (все скажут «да»), а «расскажите, как вы бронировали корт в последний раз».
2. Не питчим продукт до конца интервью. Сначала — только их жизнь и боли.
3. Конкретика: «сколько раз», «сколько денег», «покажите переписку», «что сделали потом».
4. Комплименты и «классная идея!» — не данные. Данные — это факты, деньги и обязательства (LOI, предзаказ, интро к другому владельцу).
5. Записываем дословные цитаты сразу после разговора (с согласия — диктофон).

## Критерии решения (gates)

| Сигнал | Go | Осторожно | Пересмотр модели |
|---|---|---|---|
| LOI клубов | ≥3 | 2 | 0–1 |
| Клубы, ведущие учёт «тетрадь/Excel» и страдающие от этого | ≥60% | 30–60% | <30% («у всех уже есть система») |
| Игроки: бронирование сейчас — «боль» (примеры срывов, потерянных броней) | ≥50% | 25–50% | <25% |
| Готовность к предоплате (при гарантии возврата по правилам) | ≥40% | 20–40% | <20% → усиливаем «оплату на месте» |
| No-show по словам клубов | ≥10% броней | 5–10% | <5% (ценность предоплаты слабее) |
| Юридика | нет блокеров | есть решаемые | блокер (напр., запрет модели агрегатора) |

**Важно:** негативный результат — это тоже успех Sprint 0: мы сэкономили 3 месяца разработки. Возможные пивоты: чистый B2B SaaS для клубов без маркетплейса; фокус на «оплате на месте» с депозитами; старт с тенниса/бадминтона, если падел-рынок окажется слишком мал.

## Сводный отчёт (результат спринта)

Одна страница: карта рынка (клубы, корты, цены, загрузка), топ-5 болей каждой стороны с цитатами, список LOI, юридические выводы, решение по gates, скорректированные параметры PRD (например, реальный баланс онлайн/на месте).
